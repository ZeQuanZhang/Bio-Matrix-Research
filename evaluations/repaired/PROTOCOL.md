# 修正版本地架构对比协议

2026-11-03。独立于已冻结 V3 和 tiny_arch 结果。用于修正数据、监督、验证与基线适配问题；不更改历史模型定义。

## 条件与固定预算

- 七个预先指定配置：Transformer128、Transformer512、Bio静态、Bio动态、Qwen3.5微型、DeepSeek-V4原微型、DeepSeek-V4均衡微型。
- 各配置总参数约333K，差异限制为0.1%；使用同一个4096词BPE、同种子的相同随机词嵌入，其余采用各架构原生初始化。Bio相位机制完整保留。
- DeepSeek均衡配置将mHC流数改为2、专家中间维改为20、query低秩改为8，满足本机grouped-MM对齐要求；参数333,243。原4流/专家维8配置单独保留对照；两配置分别报告，不汇总为家族择优成绩。
- 每配置用种子101搜索预训练学习率，再从该阶段选定的同一检查点独立搜索问答学习率。每阶段候选均为0.0003、0.001、0.003。
- 每个预训练搜索候选看到262,144个文本目标（batch8、64次更新）；每个问答搜索候选64次更新、512次抽题。搜索属于有限预算敏感性检查，未承诺覆盖最优参数。
- 最终种子11、23、37各从零预训练1,048,576个文本目标（256次更新），随后512次问答更新、4096次抽题。每阶段各模型输入/mask逐步核对。
- 额外七组学习链路诊断：每模型用相同8道真实短问答训练512步，学习率0.003；检查答案NLL、首token准确率和实际生成EM。控制组结果单独报告，不参与开发集选择或最终排名。
- 共91个训练阶段任务：7个学习链路诊断、42个学习率搜索、42个最终训练阶段；对应21个最终模型。全部原始数值与阶段检查点留存。

## 数据与监督

官方固定版本 WikiText-2 raw 与 SQuAD v1.1；只使用已下载并核验哈希的文件，不访问过期远程机器。

预先利用两个任务开发/保留测试文本的规范化连续32词指纹，移除训练来源中重合的文档或段落；随后仅在清理后的WikiText训练文档拟合新BPE。使用128位BLAKE2b指纹；不执行语义去重。

问答保留完整原始标注段落，不按答案位置裁剪，不排除近处答案或首token。统一限制完整证据+问题前缀≤448 token、答案≤64 token；超长样本明确排除并记录。答案和EOS参与监督，输入上下文、问题和PAD不计损失。SQuAD官方train按文章哈希切分开发集，官方dev保留为项目最终测试。

当前准备后数量：WikiText train622文档/3,054,426 token，validation60文档/322,830 token，test62文档/368,194 token；问答train80,260题、validation3,877题、test10,121题。预处理排除了7个训练WikiText分段文档和5个训练SQuAD段落的长片段重合。

## 验证、选择和保留测试

- 文本开发和测试采用逐文档覆盖评分：每个非BOS目标位置恰好评分一次，每段使用最多256个前置token并评分后续最多256个目标。没有随机重叠窗口的重复计数。
- 预训练学习率只根据完整文本开发集NLL选择；问答学习率只根据完整问答开发集答案+EOS NLL选择。选择种子与最终种子独立。
- 全部学习率选择和最终训练完成后，统一打开保留测试；不根据测试表现选择模型、学习率或检查点。
- 分别评分预训练检查点与问答后训检查点的完整文本测试，防止将后训退化混入预训练结论；问答teacher forcing覆盖全部10,121道合格测试题。
- 实际生成按答案证据距离≤128、129–256、>256三桶，每桶固定抽取64题，所有模型和种子共用同一组192题。报告每桶EM/F1及按各桶总体题数加权的EM/F1。贪心生成，最多64token，遇EOS停止。
- 同192题进行无关文章替换、远处上下文替换；完整证据与问题仍在当前输入的独立任务子集，额外插入64个无关历史token。保留正常/干预配对NLL及正常/无关上下文生成。远距离效应单独报告>256桶。
- 三种子、文章聚类的交叉bootstrap共20,000次，报告95%区间及六个对比的名义Bonferroni调整区间。记录同预训练目标的unigram控制。

## 执行与范围

使用原生Mac MPS、FP32、共享AdamW参数组、0.01权重衰减、梯度裁剪1、阶段独立热身/余弦学习率。DeepSeek保留原生0.001负载均衡辅助项并单独记录；原生初始化、实际FLOPs和状态结构不同。本轮不声称等FLOPs或旗舰CUDA速度对比。

入口：[run_biomatrix_repaired.py](../../run_biomatrix_repaired.py)。PyCharm选择“Bio-Matrix 修正版架构对比”，启用模拟终端。首次运行训练；已有活跃任务时自动附着查看；已有任务可直接再次Run附着；命令行`--mode follow`只查看。运行中保持冻结源码不变。每秒原位刷新详细条、阶段、损失与资源，不逐步打印。

状态分为not_executed、running、completed、failed、aborted；保留测试另存执行状态。支持从同一目录恢复；源码、数据、包版本及协议不一致时拒绝混用。原实验所有文件在开始和结束时核对哈希。

本轮仍属于333K规模研究。当前协议提高测量和比较的可信度；更大规模、跨领域任务、长期连续会话和专用GPU算子的结论需要后续实测。

## 从公开副本重建数据

本机已有固定来源，训练期间无需执行下列准备。新机器先按`evaluations/tiny_arch/README.md`安装固定Transformers运行环境及项目依赖，然后运行：

```bash
python scripts/prepare_repaired_sources.py
python run_biomatrix_repaired.py --mode prepare
python run_biomatrix_repaired.py --output results/repaired/my_corrected_run
```

来源准备器核验或下载官方固定文件；已有历史数据仅校验，缺失时才新建。问答原文、编码数据和检查点不随公开仓库发布；新机器从公开来源重新准备。实际训练源码、数据和包身份会再次写入新运行协议。

## 补充诊断登记

正式保留测试评分前，另行登记了纯答案先验控制：空答案、训练集最常见规范化答案、训练集最常见首答案token。补充源代码哈希与登记时点保存在运行目录`prior_control_protocol.json`；这些控制在主实验全部完成后执行，不影响模型和学习率选择。用于检查非零问答指标是否仅来自答案先验。

七种配置还通过独立的512-token、371位置非整块边界因果性/前缀检查，以及完整长度CPU/MPS输出和梯度一致性检查；脚本为`scripts/repaired_additional_checks.py`，结果见运行目录`additional_checks.json`。该检查使用单独模型，生产检查点和71份冻结运行源码保持不变。

在保留测试前另行登记文本历史干预：读取全部21个最终预训练检查点，使用128个按文档轮转抽取且评分目标不重叠的测试窗口，只评分尾部128个真实目标；将最远128输入或整个384-token前缀替换成其他文档，目标保持不变。补充协议及源代码哈希见运行目录`lm_history_control_protocol.json`，执行脚本为`scripts/repaired_lm_history_controls.py`；在主实验完成后执行，不影响模型选择。此项把文本任务的历史利用与问答学习能力分开测量，探索性区间单独解读。

额外文本计数诊断在保留测试评分前登记：用每种子完全相同的1M预训练转移计数，拟合仅依赖前一个token的平滑二元模型，平滑强度由训练中的后继类型数确定，不用测试或开发分数调参。其符号状态容量与神经模型不同，作为解释文本学习内容的补充控制，单独报告。见运行目录`bigram_control_protocol.json`和`scripts/repaired_bigram_control.py`。

独立开发批次校准比较16与64，数值检查通过，速度收益随配置不同且计时包含预热和并发影响。本轮主实验保留冻结batch16；校准详见运行目录`eval_batch_calibration.json`和`analysis/CALIBRATION_NOTES.md`。

测试评分前给文本历史补充控制增加一个保留当前输入token的条件：只替换前383个输入，位置383及全部128个被评分目标不变。仅依赖前一个token的二元预测器在此条件下严格不变，因此该控制有助于识别额外历史内容作用。原先替换前128和384输入的条件继续执行；初版脚本与登记保存在运行目录`analysis/design_history/`，修订日期和代码哈希写入`lm_history_control_protocol.json`。

“Bio静态”指单个序列内节点key/相位地址固定，节点value仍随历史写入；全局地址参数仍参与训练。动态/静态配对检验地址动态调整的额外作用；是否实际利用历史，还需结合内容替换干预。

文本历史诊断同时保留首个续写目标、前32目标和全部128目标的效应及区间，并保存逐位置均值；用于观察teacher forcing逐步提供新正确输入后历史效应的衰减。MPS损失先移至CPU再以float64累计。独立单token预测器自检确认：保留当前token时历史替换效应严格为0；改变当前token只影响第一个评分位置。见运行目录`lm_control_smoke.json`与`scripts/test_repaired_lm_control.py`。
