> 归档说明：本文保留写作时点的设计或状态。项目已停止v0.9后续训练；最新执行状态见[实验索引](../docs/RESULTS_INDEX.md)。公开副本不含权重与语料。

这是独立的 **v0.8-C + F1 + R1 工程候选**。v0.7 文件、旧检查点和远程取回结果均未改动。本目录实现讨论后的新动力学，不能把它叫成 v0.7 的等价提速版，也不表示 V08_IMPROVEMENT_PLAN.md 的 S/E/H/M/G 所有研究条件都已完成。

## 运行

PyCharm 运行项目根目录 `run_biomatrix_v08.py`，或选择运行配置 **Bio-Matrix v0.8 验证与测速**。配置启用了 Emulate terminal；总条件条和当前条件条在原位置每秒刷新。默认使用 Apple GPU，MPS 不可用时报错，不静默回退 CPU。

```bash
.venv/bin/python run_biomatrix_v08.py --device mps
```

默认 N=32/128/512、B=2、T=64、d=8、3 时间带、4 轮空间传播、FP32、6 次预热和 3 次主计时，另外单独做一次分阶段剖析。6 次预热包含 Transformer KV 达到窗口上限后的新形状预热。输出为新的 `results/v08/benchmark_时间/`，已有目录拒绝覆盖。

```bash
# 纯 CPU 明确选择；CUDA 机器明确选 cuda。
.venv/bin/python run_biomatrix_v08.py --device cpu --nodes 32 --scope model
# 同样的实现可以测更长训练块，仍采用真实反向和 AdamW 更新。
.venv/bin/python run_biomatrix_v08.py --device mps --sequence-tokens 128
# 正确性检查。
.venv/bin/python -m unittest v08.test_recurrence v08.test_model v08.test_benchmark -v
```

不访问过期的 A800，不重新下载数据，也不默认启动长时间预训练。

## 实现内容

- 每个节点保留完整快矩阵、多时间带、慢经验矩阵、m/P 概率状态、Joseph 更新、trace/support/innovation、相位和有限信用槽。
- 内外动态矩阵分别生成接收查询和输出内容；Frobenius/余弦匹配决定定向注意力，保留 Fourier 相位调制、跳跃阈值、绝对幅度门、合法边 mask 和零消息候选。
- 球图保留同层及双向连接，每轮使用同一旧快照。当前输入真实经过入口及合法边传播；块内各位置只读取其自身输入和块起点上下文，系数不依赖尚未计算的块内快状态。
- R1：正交的 width→d² 内容投影从入口注入完整矩阵，经图传播后在读口贡献有界残差；初始系数 0.1。没有 embedding→最终 head 的直接旁路。使用 `v08.model.initialize` 保留入口正交初始化。
- F1：停止局部写入方向对 head/编码参数的间接梯度，仍保留学习速率 eta、旧 slow 和未来慢经验读出的梯度。
- 相位使用已知角增量的共旋坐标表示；快矩阵的读取视图及块边界限幅，块内原始递推不逐 token 非线性裁剪。
- 块末仍按时间顺序执行已观测反馈、慢经验方向容量投影、概率与痕迹更新。末尾预测留 pending，下一块首输入到达后消费；优化器更新后旧 head 信用失效，记忆内容保留。
- 到达一致性修复：未达到现有观测阈值的最终新鲜 value/key 不进入快态地址，与 m/P 的到达判断一致；历史 transport 和 R1 内容通路继续保留。这避免零信号双重归一化的 STE 梯度被错误当成观测地址。

## 同一快递推的三种实现

共同方程：

`H_t = alpha_t H_(t-1) (I - beta_t k_t k_t^T) + beta_t v_t k_t^T`。

1. `sequential_delta`：rank-one 顺序参考，工作量 O(Td²)。
2. `parallel_delta`：Hillis–Steele 仿射前缀扫描，log₂T 轮，O(Td³logT)，物化局部 d×d 过渡矩阵。
3. `triangular_delta`：单位下三角系统求解全部写入，再批量重建全部状态；O(T²d²+T²d)，显式 T² 小块；无 token 循环、无累计衰减除法，支持 alpha=0。

后两种都增加工作量来缩短依赖链，实际可能更慢。没有构造 (Nd²)×(Nd²) 的全局稠密矩阵。完整慢提交仍有 T 步串行工作，不能把整个网络宣称为一次 GEMM。

## 校验与计时边界

CPU FP64 检查前向、所有末状态和全部参数梯度，另外检查 FP32 硬 STE 门、未来扰动不改变过去输出、完整块调用一致、重置、全关闭消息、相位/概率与容量边界、实际参数更新。每次测速前另在指定设备进行标准 d8 FP32 整网 sequential/triangular 对照并保存逐参数梯度误差。

数据复用冻结 WikiText-2 官方切分和仅训练集拟合的 4096 BPE。原始数据与准备产物都校验 SHA-256。每个规模的所有模型使用相同连续训练窗口；输入驻留设备，计时包含前向、CE、反向、clip、AdamW、状态 detach 和旧信用失效。数据采样、保存、控制台输出及预热不计入主计时。

整网对照：v0.7-full H32、v0.8 sequential C16、prefix C16、triangular C16/C32、参数接近的两层 Transformer。Transformer 的宽度和 FF 大小按参数量选择，完整配置与实际参数数目公开；状态容量照实报告，没有声称完全相同。T 至少 64，使 C32 也有两个块，局部速率参数能够获得跨块学习信号。

**只有同 C 的三实现是保持动力学的速度对照。** C16/C32 改变反馈时序；v0.7/v0.8 改变模型。旧 v0.7 保留内置诊断，整网比包括该实现成本，不能精确归因于架构。另提供纯递推核，帮助分辨快状态计算与其他工作。

## 输出与当前限制

每个条件保存 `raw.jsonl`、`result.json`，整网条件还保存 `last.pt`（模型、优化器及运行状态）。全局保存源码快照与哈希、数据/设备环境、验证日志、原生设备误差、注册表、汇总和 `REPORT.md`。状态区分 not_executed/running/completed/failed/aborted。

本次验证计算正确性和本机工程吞吐。几次 AdamW 更新不能证明语言质量、长期记忆和规模收益；大梯度仍须分析。MPS 内存记录是快照，三个主计时样本也不是正式置信区间。

完整块调用具有一致时序；不足 C 的调用会提前提交边界。**保持同一块时序的逐 token 生成 API 尚未实现**，`step` 明确拒绝调用，防止意外走回继承的 v0.7 动力学。训练和推理的完整协议验收、长期训练、S/E 正式归因及 H/M/G 支线仍标为未执行。

当前只支持全有效文档块；padding、块内 reset、块激活 checkpoint 不支持。`last.pt` 是工程快测快照，没有包含并验证精确恢复所需的 RNG 和数据游标。

## 首轮故障与修复记录

首轮 `results/v08/mps_20261024_c16_c32/` 保留 33 个完成条件和 3 个失败条件。N32 C16 三种实现均在第二次更新时触发非有限总梯度检查。CPU 重现发现梯度元素仍有限，真实 FP64 总范数约 6.4e19，FP32 范数计算溢出；未到达节点的零键连续归一化是主要放大路径。

到达一致性修复只屏蔽最终未观测的新鲜 value/key，未关闭检查、修改优化器或整体 detach 状态。同初始化和数据的三步 CPU 总梯度范数约 2.42/1.64/1.68，复测与旧失败运行分目录保存。

诊断脚本与原始数值位于 `results/v08/diagnosis_20261024/`；旧版诊断脚本读取首轮不可变源码快照。当前内容传到读口仍很弱，少量更新后的 content_projection 梯度很小；数值稳定不能当作已经有效利用当前输入或历史的证据。
