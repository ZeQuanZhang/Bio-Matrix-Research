# Bio-Matrix v0.6 公开任务实验协议

> 归档说明：本文保留写作时点的设计或状态。项目已停止v0.9后续训练；最新执行状态见[实验索引](RESULTS_INDEX.md)。公开副本不含权重与语料。

本版独立使用 `v06/`、`configs/v06/`、`results/v06/`、`data/v06/`。v0.4/v0.5 及更早实验不改名、不重跑、不混入结果。核心目标是验证完整有限状态网络能否训练，以及协作与规模对公开语言建模和历史适应的作用。

## 数据与评分

采用 [Salesforce WikiText](https://huggingface.co/datasets/Salesforce/wikitext) 的 `wikitext-2-raw-v1`，冻结 revision `6231e49f19a707241d6b84d9cff60a3a86b85a85`。保留官方 train / validation / test 切分。三份 parquet 分别校验仓库提供的 LFS SHA-256。许可按来源标注 CC-BY-SA-3.0 / GFDL。

顶层标题划分文档；小节属于原文档。归一化整篇文档哈希跨切分交集必须为零，100 字符以上完全重复段落的交集另外披露。当前实际校验为 0 个跨切分整篇重复、0 个长段落重复。train=629 篇 / 3,084,660 BPE token，validation=60 / 322,869，test=62 / 368,123。

byte-level BPE 词表 4096，仅在 train 拟合；每篇加入 BOS/EOS。训练窗口始终位于单篇文档内，从全部合法起点均匀抽样；配对条件以 data_seed、模型重复种子和更新编号确定同一批输入。不存在测试答案、情境编号、隐含程序或外部历史库进入模型的通道。

主指标是每组固定的公开测试窗口逐 token NLL 与本分词器 PPL。默认 dev 8 窗口、test 24 窗口，每窗口 64 个前缀和 64 个计分目标。测试窗口对所有模型完全相同，保存内容哈希与可复建起点。它是公开任务上的窗口化评分，不冒充官方全量 word-level PPL。默认窗口数量适合初筛，置信区间与泛化结论需要更大的固定测试预算。

## 已实现的节点与网络

每个样本只有一份持续网络状态，不配置情境副本。默认 d=8、3 时间带、3 相位模式、2 资格迹时间带、固定 8 个入边候选、4 层球壳、每输入 4 轮内部计算。球壳按体积近似分配节点；几何位置与内容特征分开。

| 状态 | 每条流形状 | 用途 |
|---|---|---|
| m / p / slow / response | 各 N×d×d | 快记忆、列空间协方差、局部慢参数、有限传播响应滤波 |
| x | N×bands×d×d | 多时间尺度载波 |
| trace | N×trace_bands×d | 固定容量资格迹 |
| support | N×d | 有界重复支持度 |
| z | N×modes×2 | 实部/虚部形式相位 |
| innovation / evidence_count | 各 N | 创新量与事件计数诊断 |
| prediction | width | 上次预测的嵌入期望，供新 token 到达时的局部反馈 |

节点另有 N×d×d 的可训练初始形状参数。新 token 只向中心注入。消息包含 d×d 载波与固定 2d+1 的新事件包，不附加路径、导数或历史。候选连接包括径向父节点和壳内连接。向外需达到强度/内容/状态门槛，向内和同壳不施加该跃迁门槛；候选拓扑仍限制传播范围。

内部/外部矩阵之间的映射使用可训练对角项、状态调节的秩一项及结构化行列旋转，避免每轮任意 d³ 双侧稠密乘法。多维 Fourier 调制保留单模式和相邻模式交叉项。局部相位耦合叠加在节点内频率上。相位调制载波采用保范旋转，衰减由显式时间带负责，不额外统一强衰减所有时间带。

每个 token 的新事件包在内部循环传播，同一事件沿多条路径到达后作为一个聚合观测；协方差只在输入事件结束时对到达节点更新一次。使用 O(d²) 的 Joseph 外积重排并显式加入 1e-6 对角抖动。协方差针对 d 维列空间，每个值行共享；不创建 d²×d² 协方差。自然文本存在相关性，这些统计是可训练的近似不确定性机制，独立证据计数的诊断不能证明统计校准。

节点局部慢更新利用：新可见 token 对上一时刻预测造成的嵌入误差、投回矩阵特征空间的有符号反馈、有限资格迹、路径响应滤波、重复支持及一致性门。仅根据已经到来的输入更新，不读取尚未出现的下一个 token。响应滤波使用标量传播算子的近似伴随，不存完整路径或全雅可比；非线性旋转/映射的完整导数由全局 BPTT 处理。该局部规则是 Filtered-x 启发的可检验近似，不宣称等价于精确在线梯度。

## 配对模型与公平边界

| 名称 | 定义 |
|---|---|
| message / C1 | 相同矩阵状态、拓扑、端口、跃迁与局部学习骨架；载波使用普通 MLP 消息变换，移除相位/Fourier 载波 |
| independent / C2 | 振荡/Fourier 载波，关闭显式节点间相位耦合；节点仍接收普通内容消息，因此不称完全解耦的孤立节点 |
| full / C3 | 完整局部耦合 v0.6 |
| transformer | 从零训练的两层 pre-LN、RoPE、因果 SDPA、GELU FFN、共享输入输出嵌入；搜索有效宽度/FFN 使参数接近 full |

三种图网络使用相同消息/状态形状、邻接、读写路径和更新预算；共享名称与形状的参数用独立按名称播种的生成器得到相同初始化。Transformer 不填充无用参数；参数匹配误差、KV 状态与实际运行成本另报。默认 core 的 full 参数量约 309k / 315k / 340k，匹配 Transformer 约 306k / 306k / 345k。总参数包含嵌入、输出与节点初始形状。

所有模型每组 4000 次 AdamW 更新、batch=2、序列 64，目标 token 预算 512,000。学习率 3e-4、200 步 warmup、cosine decay、weight decay .01、梯度裁剪 1。每 16 token 截断状态梯度，状态内容继续传递，整个窗口累计梯度再更新一次；Transformer 同样 detach 旧 KV。各架构尚未独立调参，因此首轮只评价此固定训练方案。

训练前 400 步由软门逐渐过渡到硬门的代理梯度。验证和测试始终采用硬门，保存 soft/hard 差异可见的训练曲线。训练 loss 与验证 loss 的计分位置及上下文长度不同，应结合各自的变化判断。

## 条件顺序与补充

core：32 / 128 / 512 节点 × 四种模型 × 三种子=36 条件。每种子的一个规模先完成四种模型，再扩大规模，首轮三个规模完成后补下一种子。不要求单节点先获胜。

补充 24 条件：

- mechanism：128 节点，依次关闭局部更新、慢记忆、概率更新、动态映射、时间带区分、向外门槛。
- iterations：128 节点，independent/full 各比较 J=2、8，core 的 J=4 为参考。
- topology：128 节点三种图模型切断中间球壳边界，固定原候选邻接和端口。
- capacity：三种图模型在 (N,d)=(32,32)、(128,16)、(512,8)，固定 N d²=32768。**这是相同矩阵容量，完整总状态受相位/迹等线性项影响并非精确相等**；ledger 报告真实字节。实际运行前需按这一阶段重新剖析。
- credit：32 节点 full/no_local 使用完整 64-token BPTT，比较局部规则与截断误差。

这里匹配训练数据、曝光量及图模型状态预算；没有伪称所有模型具有相同 FLOPs、状态或墙钟时间。额外计算匹配实验应根据本机测速设定并单独登记。

## 历史干预

所有干预计分相同的 A 文档续写目标，当前可见 token 完全相同：

1. carry：A 前缀 → A 续写。
2. reset：没有前缀历史，从 A 续写当前 token 开始。
3. shuffled：打乱 A 前缀顺序 → 同一 A 续写。
4. unrelated：另一篇 B 的等长前缀 → 同一 A 续写。
5. A_B_A：A 前缀 → B 前缀 → 同一 A 续写。
6. unrelated_boundary：B 前缀 → EOS/BOS → 同一 A 续写，单独检查显式边界的影响。

模型只看到普通 token；A/B 编号不输入。测试不运行优化器，允许架构定义的运行时局部更新。记录每个位置 NLL、carry 分布到其他条件的 KL、top-1、置信度、ECE，以及前 16 token 的适应损失。

相关历史收益=reset−carry NLL；无关历史代价=unrelated−reset NLL；返回代价=A_B_A−carry NLL。自然文本不提供因果独立性的严格证明，这里测的是人为插入不相关文档历史造成的干扰。它不替代受控来源依赖、异常噪声和带真值反馈的机制诊断。

主要成功依据是多个独立种子下稳定的公开任务 NLL 改善，并同时审视历史使用、无关干扰与实际成本。保存配对窗口差值和各种子的平均差值/标准差；窗口不充当额外独立种子。同步曲线、单次准确率或两步 smoke 不构成成功结论。首轮测试样本较小，正向结果应在扩大预先固定的测试集合与训练预算后复核。

## 工程验收与暂停恢复

先检查形状、因果性、梯度、协方差正定性、球壳方向、固定状态大小、事件去重计数、重计算一致性和恢复一致性，再进行本机 MPS 资源剖析。状态计数、训练激活、进程 RSS 和 MPS driver 快照分别记录；快照不称为隔离峰值。

正式实验由用户在 PyCharm 启动。当前允许短程工程检查和资源测量，正式结果在独立条件登记中从未执行开始。源码、配置、数据或设备变化时拒绝混用旧检查点。模型保存共享权重与 runtime state 时才能保存后天经历。
