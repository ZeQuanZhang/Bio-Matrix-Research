# Bio-Matrix v0.9 训练速度优化方案

> 归档说明：本文保留写作时点的设计或状态。项目已停止v0.9后续训练；最新执行状态见[实验索引](RESULTS_INDEX.md)。公开副本不含权重与语料。

日期：2026-10-25。对象为当前本机 MPS 上的完整 v0.9，以及未来重新取得 CUDA 设备后的实现。现有正式训练、数据、预算和结果继续保留；本方案只新增研究文档与 CPU 内存账本。

**建议同时推进两条主线：扩大单次训练真正同时计算的独立序列数；用等价数学重写、编译和融合减少空间传播与慢状态更新的细碎计算，并同时优化反向。** 完整内外矩阵、振荡、概率状态、信用和局部反馈先全部保留。更改传播图、更新频率或状态表示的方案放到后续独立对照。

显存空余提供了扩大并行工作的空间。优先让更多独立会话的状态和激活同时参与计算，而不是把无用副本留在设备里。最终按有效目标/秒，以及达到同等质量的墙钟时间决定方案。

### 1.2 旧 A800 的经验

旧 v0.7 A800 的 12 路混合短测达到 2,104.28 有效目标/s、GPU 忙碌时间 96.67%，显存峰值只有 16.12 GiB；当时容器为 14 核 CPU 配额。后续增加到 14 路提升了总吞吐，16 路反而回落。原始记录说明 CPU、提交方式和任务调度确实会限制这个网络，也说明“80G 只用约 20G”不足以直接判断性能浪费。[A800 原始调优报告](../results/v07/remote_a800/utilization_audit_20261023T042807Z/TUNING_REPORT.md)、[执行记录](V07_A800_EXECUTION.md)

### 1.3 已经实现的优化

当前已经有低维地址、完整矩阵 value/state、对角加低秩动态映射、控制量复用、批量反馈方向计算、rank-one Joseph、全激活直接路径，以及三种快递推实现。这些要继续使用，不能重新包装成新收益。

当前 d8/C16 的 MPS 短测选择顺序 delta。并行扫描和三角求解已有参考实现；它们在更大 d/C 或 CUDA 上可以重新测，但没有理由直接替换当前较快路径。当前也未开启事件级 activation checkpoint 来主动省激活显存。

## 2 把更多有效工作放进显存

### 2.1 当前状态实际有多大

CPU 上仅构造当前正式形状的完整 dense 模型和初始运行态，按 tensor 的逻辑字节与去重 storage 字节分别统计，两者相同。以下包含 m、p、x、slow、相位、trace、response、support、信用缓存和组摘要；不含训练中间激活、反向图、驱动分配和编译工作区。

| 节点数 | B2 初始运行态 MiB | B8 初始运行态 MiB | B32 初始运行态 MiB | FP32 参数 MiB |
|---:|---:|---:|---:|---:|
| 32 | 0.229 | 0.914 | 3.657 | 1.205 |
| 128 | 0.818 | 3.273 | 13.091 | 1.228 |
| 512 | 3.177 | 12.706 | 50.825 | 1.322 |

这解释了为什么仅增加“保存多少个旧状态”很难吃满大显存。大头往往来自同一轮训练保存的节点轨迹、边消息、中间变换和反向所需值。表内也不含参数梯度和 AdamW 两份 moment。训练后的状态还可能用 view 保留比逻辑大小更大的底层 storage，例如最后一帧 x 和截断信用缓存；P0 要在暖态完整更新后同时统计 logical/unique storage，再测反向峰值。旧 v0.7 N512/B2/T128 的 CUDA 分配峰约 9.77 GB，不能把几 MiB 的初始态当作整次训练的显存需求，也不能用旧峰值直接预测 v0.9。

本次账本：[memory_ledger_cpu.json](../results/v09/speed_plan_research_20261025/memory_ledger_cpu.json)。只执行 CPU 构造和计数，没有启动新训练或分配 GPU tensor。

当前训练的参数和核心 Bio 运行态本来就在训练设备上，普通更新没有每 token 把整份状态搬回 CPU。取回 CPU 的主要是诊断标量、保存快照和 sparse 路由决策。后续增加常驻内容应针对这些实际边界，而不是寻找一个额外的“让状态使用 GPU”开关。

### 2.2 第一选择是真正扩大 batch

当前 batch=2。候选阶梯为 **B2→4→8→16→32**，在吞吐进入平台、内存压力过高或尾延迟恶化时停止。每个 lane 是独立连续会话，持有自己的全部 Bio 状态；共享模型参数，在同一次前向和反向里批量计算。

例如 B2×T64 每次最多产生 128 个有效目标，B16×T64 最多 1024 个。当实际有效目标数约为八倍时，B16 一次更新用时小于 B2 的八倍，总吞吐就会提高；严格按耗时比例与实际目标数比例判断，计入接缝 mask。具体提高多少由测试确定；batch 增大后也可能受访存、路由拆批和反向限制。

增加的显存用于更多有效序列的状态与激活。节点数、矩阵维度、传播轮数和模型参数保持相同，先单独检验 batch 的作用。梯度累积仍以 B2 跑八遍时，每个 kernel 看到的工作量依然小，不能获得与真正 B16 相同的并行程度。

**batch 变化要单列训练条件。** 固定有效目标预算下 optimizer 次数减少，AdamW 的步数和累计衰减改变，数据 lane 调度改变，按总 token 定义的课程也会在不同的每会话进度生效。每个 lane 的 C16、T64、时间常数和反馈顺序先不变；学习率与课程仍按真实有效目标计数。先比较相同学习率，再对选出的 batch 做小范围学习率调整，避免盲目按 batch 倍数放大学习率。

大 batch 的吞吐收益会遇到统计效率边界。梯度噪声尺度可作为后续选择 batch 的诊断，当前先用吞吐曲线与固定预算质量检验确定范围。[An Empirical Model of Large-Batch Training](https://arxiv.org/html/1812.06162v1)

### 2.3 更多显存还可以存什么

| 内容 | 具体做法 | 对速度的作用 | 边界 |
|---|---|---|---|
| 独立会话状态与激活 | 按 batch 维同时计算，保持每个会话身份和 reset | 增加每个 kernel 的有效工作 | 不混历史，不把未来块提前更新 |
| 前向已计算且反向需要的量 | 保留必要中间量，减少自定义 backward 的重复计算 | 用存储换重算 | 选择性保存，不能留全部冗余边消息 |
| 固定图与索引 | 邻接、合法父边、mask、路由槽和临时缓冲常驻 | 减少分配、索引构造和搬运 | 稀疏 active IDs 或图版本变化须更新 |
| 多次使用的同一块投影 | 同一 forward 内复用并保留梯度关系 | 减少重复投影 | 参数更新后失效；依赖块起点状态的量跨块失效 |
| token 数据和下一批输入 | 训练 token 常驻或双缓冲预取 | 减少小次传输与主机等待 | 目前数据已经 mmap 和预分词，预期优先级低于计算热点 |
| 稳定地址的输入和工作区 | 固定 shape 后复用缓冲，未来适配 CUDA Graph | 降低分配和提交成本 | autograd 未消费的旧值不能原地覆盖 |

当前 train token 文件约 12.34 MB，转 int64 约 24.68 MB。全放设备很容易，但这点传输不是现有空间/反向耗时的主要解释。可以做，放在更有价值的 batch 和计算优化之后。

Mac 使用统一内存，CPU 和 GPU 共享物理内存资源；增加设备分配也会影响系统内存压力。当前 MPS 的 allocated/driver 指标与 CUDA 独立显存的账法不同。不能用每步结束时的几 MiB 快照代替反向峰值。[Apple PyTorch MPS 路线](https://developer.apple.com/metal/pytorch/)、[PyTorch MPS 内存接口](https://docs.pytorch.org/docs/2.14/mps.html)

## 3 用线性代数减少同样结果的工作量

这里的“等价”指保留原来的实数方程和梯度边界；浮点求和顺序变化另做误差验收。符号为 B 批量、C 块长、N 节点数、K 邻居数、d 矩阵维度、J 空间轮数。

### 3.1 共享输入包只传播强度

同一 token 的驱动包由共享的 value、key 和质量构成。若节点 i 收到的始终是 `a_i × packet`，图聚合可以改为只传播标量 a，最后在真正需要 value/key 时还原。

`Σ_j w_ij(a_j packet) = (Σ_j w_ij a_j) packet`

这减少 B×C×N×K 上重复搬运同一输入向量的工作，保留原始边、门控和各轮到达顺序。要逐步证明归一化、空质量和门控条件都只需这些系数；任何节点独立改变 packet 的操作，都必须留在实际改变它的位置。

当前 `drive_controls` 无 bias，还可以把 `W(a_i packet)` 改成 `a_i(W packet)`：每 token 投影一次共享包，再按节点幅度缩放。保留 mass floor、到达阈值、clamp 与 normalize 的 eps；极小幅度下不能无条件约掉归一化中的 a。

### 3.2 当前内容载体只传播到达质量

v0.9 的基础内容路径携带同一 token 的完整 fresh matrix，经合法父边逐轮到达读取节点。当前共享 fresh、基础父边恒等传递，质量 b 为 0/1；可以保存 `base_i=b_i × fresh_matrix` 的 b，**在每轮 communication 使用基础内容的位置，以及最终读取处按需生成**，减少 N 份同内容矩阵的搬运。每轮基础内容对映射、匹配、相位和快态系数的影响继续保留，不能只恢复最终 head 的基础输入。

这保留完整 d² 内容特征和图可达性，图切分后仍须断路。它只针对具有共享因子的当前内容载体；各节点已经不同的 x、m、slow 继续保留完整矩阵，不能沿用这个简化。

### 3.3 块读取直接收缩时间维

C16 读出使用块起点的 m/slow 快照。把 query 整理为 `[B,N,d,C]`，状态为 `[B,N,d,d]`，一次批量矩阵乘得到全部 query 的读取结果；避免先把状态 expand 到时间维再 flatten，导致 B×C×N×d² 的实体副本。

计算本身仍是 O(BCNd²)，主要节省状态复制、临时存储和 kernel 调度。关注 permute/reshape 后是否真的触发 contiguous 拷贝，不能只凭代码行数判断。

### 3.4 Joseph 与 slow 容量投影继续精简中间量

Joseph 已经是 O(d²) rank-one 更新。令 `r=P_prior k`、`s=kᵀr+R`、`z=weight/max(s,1e-6)`，其三项外积可合成 `(-2z+s z²)rrᵀ`，然后沿用原对称化和 jitter。保留实际 s 与 floor 后分母的区别，融合先验对角项，减少读写；复杂度仍为 O(d²)。

slow 投影可利用 `S - (Su)uᵀ` 的 rank-one 结构，通过向量和矩阵范数计算正交部分容量，再只构造最后一次外积更新，避免反复生成完整临时矩阵。实际代码采用带 eps 的 normalize；不能直接假定 u 严格单位长。容量边界、零 query、零半径和原本的子梯度都要逐项保留。

这些候选对应现有空间和慢提交热点。它们通常同时减少前向实体工作和 autograd 需要记录的中间量，优先于直接扩大网络来填内存。

### 3.5 邻居聚合与结构化映射

对于“边上只有标量权重，发送端 value 对所有接收者相同”的区域，候选是把 d² 展平成 feature，使用分块 gather-reduce 或适配后端的稀疏矩阵乘。若变换依赖接收节点或每条边，则保留边局部计算，不能硬套同一个全局乘法。

现有动态映射已经是对角加低秩。继续把 `U(Vᵀx)` 等收缩按较小的中间维度执行，避免先生成完整变换矩阵。常见大临时量是 O(BCNKd²)，反向跨 J 轮保留后可能更大；目标是融合产生与消费，或按节点/边块处理。

球体排布本身不提供 FFT 对角化。只有算子具有明确的平移/旋转共享、卷积或可分离结构时，傅立叶域计算才成立；当前动态门、稀疏边和图切分不能直接换成一次 FFT。受约束的谱算子可以作为后续新架构，而非当前等价提速。

## 4 减少无效反向并融合真正的热点

### 4.1 已找到的 F1 图构造浪费

当前 F1 的解析方向在计算后立即 detach。可以只对这段方向计算使用 `torch.no_grad()`，避免先创建一段马上丢弃的 autograd 图。

已有 CPU FP32、N32、B1、T32 的单样本探针：loss、logits、完整末态、全部参数梯度和旧 slow 输入梯度最大差均为 0；局部学习率参数梯度与旧 slow 梯度保留。它证明该候选在这一输入上的等价性，GPU 时间收益还未测。探针结果（本地留存：`../results/v09/speed_audit_20261025/f1_no_grad_cpu/result.json`）

**范围只限原来就 detach 的方向计算。** gain、eta、slow 旧值、容量投影和 m/p/trace 演化仍按原规则参与求导，不能对整个 local proposal 或 commit 套 no_grad。

### 4.2 把 C16 顺序更新移进设备核

保留每个 token 的更新先后，在一个设备 kernel 内循环 C16；B×N 及矩阵元素并行。这样减少 Python 循环、小 tensor 对象和每个 rank-one 操作单独启动 kernel 的成本。

前向包括原有 Joseph、slow 投影、trace/support/innovation 和反馈信用顺序；反向按原计算图做对应的逆序传播。根据显存预算保存必要中间量，或只重算便宜片段。全局 pending 消费、读取快照和下一块可见状态的边界保持原样。

这条路线把顺序依赖留在 GPU 内部。它不要求将所有 token 当成互不依赖，也不需要删除慢状态机制。

### 4.3 融合空间系数计算及其 backward

优先融合邻居 gather、局部变换、门控、相位相关点运算和归约；成熟的大投影继续交给矩阵库。减少边消息实体化，以及同一个小张量多次读写。

反向同样覆盖 gather 的梯度回填、动态映射参数、门控代理梯度和相位等路径。若仅前向快两倍，按现有前向约四成的占比，完整更新理想上也只快约 1.26 倍。必须以完整 update 验收，不能把单核加速倍数当成全模型倍数。

PyTorch 的融合建议和自定义训练算子文档支持这类执行方向；Bio 的实际收益由本地测量给出。[PyTorch 性能指南](https://docs.pytorch.org/tutorials/recipes/recipes/tuning_guide.html)、[Triton 自定义训练算子](https://docs.pytorch.org/tutorials/recipes/torch_compile_user_defined_triton_kernel_tutorial.html)

## 5 稀疏计算要变成硬件能批量执行的形状

当前 sparse50 在 N32/N128 反而更慢，N512 才提高约 22.95%。实际活跃比例分别为 100%、约 58.3%、约 50.9%。选出一半节点后，CPU 排序、子图构建、lane 拆批和回填可能吃掉收益。

候选实现为每个原静态分量固定容量的 active ID 张量与 mask，设备上完成稳定选组和 inverse mapping。B 个 lane 可以各选各的节点，但使用少量固定 shape 批量执行，尽量避免每种路线单独调用一遍网络。

必须保留 mandatory 路径、探索预算、并列分数的确定顺序、原始节点身份和 idle 冻结；padding 不参与门控、状态更新、读取或梯度。全图 pending 信用仍先消费，再 gather 当前 active 子图，图切分的两侧不得通过全局摘要传信。

dense 的全激活路径已经绕过 CPU 选组，这项主要修复 sparse，不能用它解释 dense 的全部速度差距。N32 必选路径已覆盖全图时直接走全图快路径，避免无收益的 compact。

## 6 Mac 与 CUDA 分开选择执行工具

### 6.1 当前 Mac

本机 Torch 2.14.1 已核对存在 `torch.mps.compile_shader`、MPS Signposts/Metal capture/Event、自定义算子注册接口，本地 Inductor 也已注册 Metal backend。具体算子能否成功编译、反向是否受益，需要局部试验。[PyTorch 2.14 MPS API](https://docs.pytorch.org/docs/2.14/mps.html)

先捕获短 MPS 时间线，区分 CPU 发射间隙、设备计算、访存与同步。捕获窗口用于归因，关闭捕获后另测吞吐。优先对固定形状、纯张量的 coefficients 子函数做局部 `torch.compile`；记录首次编译、重编译、图断裂与 eager 回退。

局部编译无明显收益时，再为明确热点实现 Metal 前向和反向。自定义 shader 能执行计算，不会自动为任意代码生成正确训练导数；需要显式 autograd 与编译元信息。`reduce-overhead` 的官方 CUDA Graph 路径不能直接当作 Mac 加速保证。[torch.compile 文档](https://docs.pytorch.org/docs/2.14/generated/torch.compile.html)

### 6.2 未来 CUDA

复用固定形状和状态接口，先局部 Inductor，再按热点选 Triton。CUDA Graph 用稳定地址的缓冲重放固定数值区域，以减少 CPU 提交成本。动态 route ID 的值可以改变，shape 和存储生命周期需要稳定；Python 排序、`.item()` 和文件操作留在 capture 外。

CUDA Graph 保留依赖关系，不能消除原有状态递推。先局部捕获前向与反向可行区域，再决定是否捕获完整更新；参数、优化器、RNG 和运行态恢复一起验收。[PyTorch CUDA Graph 语义](https://docs.pytorch.org/docs/2.14/notes/cuda.html)、[NVIDIA CUDA Graphs](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/cuda-graphs.html)

不连接已过期 A800；旧 v0.7 的编译和并发数字只作为实现经验。未来设备重新到位后，按 v0.9 实际形状重新测速。

## 7 同步 数据 日志和检查点

当前每步有计时同步、loss 有限性检查、裁剪检查，以及多个诊断 tensor 转 CPU。优先合并可合并的诊断读取，降低非必要诊断的计算频率；保留执行优化器前的非有限保护。连续更新窗口只在边界准确计时，避免多余计时同步，同时防止把尚未完成的异步工作漏掉。

当前数据已预分词并 mmap。先测采样与传输实际占比，再决定数据全常驻、预取或增加 worker；不要复制多个进程仅为读取这份小 token 数组。

当前 `metrics.jsonl` 每步写完整记录，`live.json` 每步前后写，父进程每秒重新生成注册表和报告。可将稳定元数据保留一次并按 ID 引用，标量轨迹仍完整保存；减少重复 JSON 序列化和原子替换。缓冲原始记录时明确最多会丢失的未落盘尾部，并在检查点、停止和异常时强制落盘。

**总条、所有详细条、阶段、loss、速率和资源行继续每秒原位更新。** UI 使用最近已提交快照和时间，不要求每秒触发一次 GPU 全局同步；长更新时如实显示仍在当前阶段，不编造完成 token。

当前每 100 update 保存 last，payload 还会读取并嵌入 best 快照。候选是测量其墙钟占比后，使用保留哈希的不可变 best 文件引用与一致归档，减少反复读写；或在新协议中以时间/有效目标定义普通 last 周期。里程碑、验证结果与停止保存继续保留。

异步保存必须先得到某一完整更新边界的一致快照，模型、优化器、运行态、RNG 和数据游标属于同一时刻。后台线程直接读取仍在更新的 tensor 会破坏恢复。源码哈希保护继续保留，不用关闭保护来换速度。

数据、UI、保存优化主要改善端到端墙钟；旧核心测速已经排除采样和保存，不能用它们解释表中的大部分核心差距。

## 8 精度 反向跨度和流水线

### 8.1 混合精度

先评估内容投影、FFN 和输出头的低精度；m/p/slow、信用、时间常数、Joseph 分母、归一化、容量约束和关键累加先保留 FP32。局部改变量可能很小，直接把长期状态存为 FP16/BF16 会抹掉有效写入。

autocast 按算子选择精度，不能只对整个模型 `.half()`。Mac 的 dtype/算子支持按本机 OS 与设备实测；CUDA 的 BF16/FP16/TF32 各自记录设置，分别测有限性、长期状态误差和质量。[PyTorch AMP 文档](https://docs.pytorch.org/docs/2.14/amp.html)

### 8.2 三种长度不能混在一起调

| 参数 | 当前值 | 改变它主要影响什么 |
|---|---:|---|
| C 执行块 | 16 | 块起点状态快照、系数复用、反馈提交与下一块可见性 |
| T/BPTT | 64 | 每次反向的时间跨度、激活保存量、梯度截断与更新边界 |
| 会话长度 | 4096 | 状态在多次更新间持续的输入机会和 reset 时刻 |

C 增大不能自动当成等价批量计算：当前块内使用起点状态，扩大 C 会延迟部分历史反馈生效。BPTT 缩短可能让训练更便宜，却会改变跨块学习；延长会多占显存，也会增加反向工作。保持原值先优化执行，之后每项单独做协议对照。

### 8.3 流水线的有效位置

同一序列的下一块需要上一块留下的状态；独立会话之间可以重叠输入准备、设备计算与快照写盘。先扩大真正 batch；当时间线仍显示可重叠空档时，再考虑多设备流或分阶段流水线。

如果要预计算未来 token 的纯内容 embedding/投影，只能在参数版本和因果规则允许的范围内批量做；依赖历史状态的系数和更新继续等待前态。不能提前使用未来 token 更新当前状态，再把它算成相同模型的提速。

多卡数据并行可以扩大总 batch，但仍须验证通信和训练效率；当前几十万参数的小模型优先解决单卡执行。模型切到多张卡并不会自动拆开时间递推。

### 8.4 显存空余时不优先做重计算

Activation checkpoint 用额外重算节省内存；目前并非首选。大 batch 真正被峰值激活卡住时，才对纯函数区域选择性使用。当前 compact 图通过临时 active 索引与图视图执行，重算必须拿到与前向相同的路由和视图，不能依赖已改变的可变属性，也不能重复提交运行态。[PyTorch checkpoint 语义与可变状态警告](https://docs.pytorch.org/docs/2.14/checkpoint.html)

## 9 后续架构路线及代价

以下会改变模型规则或表示能力，另起条件评估。完整版本继续作为参考。

| 方向 | 省在哪里 | 改变的内容 | 建议 |
|---|---|---|---|
| 多时间尺度更新 | 慢变量每若干 token 才更新 | 更新频率、累计证据和反馈延迟 | 优先考察低敏感控制量；不直接跳过有意义观察 |
| 事件触发计算 | 变化小的节点少执行 | idle 时间、衰减和不确定性演化 | 触发器也计成本；定义跳过后的精确时间语义 |
| 更少空间轮或邻居 | 减少 J/K 倍空间工作 | 传播可达性、交互深度和感受范围 | 与完整图做同状态预算对照 |
| 只向外或取消同层边 | 简化空间调度 | 原假说中的同层/回流协作 | 保留为拓扑消融，不作为默认修复 |
| 对角或分块 P | 减少协方差工作 | 跨方向不确定性关联 | 由完整 P 对照证明是否值得 |
| 低秩 x/m/slow | 减少 d² 状态和读写 | 可存内容容量、经验叠加与秩饱和 | 当前 d=8 未必划算；先做完整矩阵精简 |
| Kronecker/共享谱传播 | 利用结构化算子 | 参数共享和空间/通道耦合形式 | 需要明确可分离假设及图切分规则 |
| 更便宜的学习型路由 | 减少选组开销和无用计算 | 路由策略，可能需要额外训练 | 先解决现有规则的设备批处理 |
| 稀疏控制器蒸馏 | 学 dense 的选择或读出 | 增加训练阶段和教师成本 | 以总训练成本和最终速度评估 |

不能凭同步曲线或节点活跃率选择删模块。模块价值通过同预算消融、相关历史收益和干扰后保留检验；某一小规模暂时无收益，不取消其他规模的执行资格。

## 10 时间并行和一次矩阵计算的适用边界

当前 fast rank-one recurrence 可以用 delta 扫描、三角求解或 WY 分块重写，已有参考实现。分块线性代数能把部分顺序更新改成 GPU 擅长的矩阵乘，但 d8/C16 时额外构造和求解成本可能更高。按实际维度和后端选择，而不是统一强制 scan。

固定 C16 内的 kernel tile 可以调整，生物块边界继续固定。后续候选是融合快递推、相位/容量读取和 backward，减少完整轨迹反复落盘；多个时间带共享 key/value 和适用的 Gram/retention 中间量，各自完整状态继续独立存在。[DeltaNet](https://arxiv.org/html/2406.06484v3)、[Gated DeltaNet](https://arxiv.org/html/2412.06464v3)、[FLA 官方实现](https://github.com/fla-org/flash-linear-attention)

当前 frames/query/gain/proposal 已整块固定并批量计算，融合时继续放在顺序循环之外。真正需要保持先后的是 slow 的 query 容量投影，以及 m/P 的 Joseph 和 `bounded(m)` 对前态的依赖，它们不能直接套 fast recurrence 的闭式。进一步冻结、延迟或近似这些更新会产生新的训练条件。长远可研究受约束的仿射状态、分段线性化和多速率近似，但先用完整参考检验累积误差与历史能力。

快权重论文和 DeltaNet 类方法提供可用的分块代数与实现经验；需要按本地方程确认矩阵方向、符号、门和梯度边界。相关详细推导见[数学研究笔记](../results/v09/speed_plan_research_20261025/math_review.md)。

## 11 分阶段实验与验收

### 11.1 统一基准

冻结参考源码和若干早期/成熟检查点，优化实现使用独立目录。工程测速覆盖 N32/128/512，dense 与 sparse 的真实路线、冷态和暖态；不以小规模胜出作为大规模测试的前置资格。

充分预热至编译和分配稳定，随后至少 3 个独立计时窗口，每个 30–100 次完整 update；视耗时调整，原始时间与实际目标数全部保存。需要短 profiler 时另跑一个独立窗口，正式吞吐关闭捕获。记录：

- `sum(有效目标)/真实完成时间`，以及 update 中位数、p95 和前向/反向分项。
- 编译冷启动、重编译、峰值激活、实际状态字节、框架保留量、CPU 和系统内存压力。
- 从数据准备、训练、验证、记录到保存的完整墙钟，以及各段占比。
- 相同会话机会和真实上下文年龄下的 Transformer，不能把短上下文的旧结果套给长训。

测速保持同一 checkpoint、初态、输入、mask、reset 和 RNG。比较有状态的多次更新时，两条路径从同一冻结起点各自推进相同序列，不能让后一候选接着前一候选已改变的模型继续跑。

### 11.2 等价执行验收

比较逐块 logits、loss、所有运行态、参数梯度及 None/non-None 状态、裁剪后更新方向和短优化器轨迹。覆盖旧 slow 非零、延迟信用、reset、图切分、稀疏路线切换、idle 与长会话。

CPU FP64 用于小形状代数参照，MPS 使用 FP32；误差容限在运行前确定并记录。归约换序可能在硬门边界引发离散分支差异，因此同时记录分支和路由，区分光滑区导数检查与硬门/STE 的指定梯度检查。F1 已有显式 detach，不能拿整段有限差分强迫它变成另一套梯度。

长轨迹检查相位归一、P 对称与数值正定性、slow 容量、有限性、图切分隔离和未来输入泄漏。融合 slow 核尤其要验证 eta、旧 slow、m/p/trace 的梯度没有丢失。

### 11.3 训练质量与真实效率

等价优化先过数值和轨迹门，再测性能。batch、精度、C/T/J/K 或状态结构变化则比较固定有效目标曲线与固定墙钟曲线，最终以达到同一冻结 validation NLL 的时间评估训练效率。固定预算主结果继续用 last；best 单列，测试集不用于选优化方案。

当前暖历史协议中的 A0R/U0R、远史顺序干预和带干扰返回继续使用。clear_slow/base_only 的归因与同样信用失效的 credit_only 对齐。自然文档对照检验历史作用；严格独立后验和规则修订需要另适配公开任务。完整 Bio 优于 content_only 的冷 NLL 不能直接归因到某个状态模块。

先用 seed11 做工程排除和有限训练 pilot；候选稳定后补 seed23/37。中间多个检查点是相关观察，不充当多个独立种子。3M pilot 从一开始使用 3M 日程，不能把 12M 日程的中途检查点当作独立完成实验。

## 12 推荐实施顺序

| 阶段 | 工作包 | 保留/改变什么 | 通过条件 |
|---|---|---|---|
| P0 | 补峰值内存、端到端账本与短前向/反向时间线 | 只观察 | 能区分提交、算术、访存、记录和保存 |
| P1A | F1 无效图、共享驱动/载体因子、块读取布局、投影中间量 | 保留方程和训练协议 | 数值/梯度/轨迹通过，完整更新稳定更快 |
| P1B | 单任务 B2/4/8/16/32 阶梯 | 模型结构保持，训练方案变化 | 找到吞吐平台与内存边界，候选再比质量 |
| P1C | sparse 固定容量路由与跨 lane 批处理 | 保留原选择规则与图边界 | 真实 active ratio 相同，N128/512 端到端获益 |
| P2 | coefficients 局部编译/融合，C16 commit 设备循环与 backward | 保留原状态时序与导数 | 热态整次更新获益，编译成本可摊销 |
| P3 | 选择性混合精度、输入常驻、记录与一致快照优化 | 精度另列；I/O 保留恢复能力 | 同质量墙钟更短，长状态稳定 |
| P4 | 更新频率、传播图或状态结构改变 | 新架构对照 | 质量、历史能力与速度共同评估 |

P1A 与 P1B 可以在独立实现中并行研究，分开报告再合并；当前正式队列保持冻结。每阶段先单项定位，再组合有效项，不做 batch×精度×C×图×状态秩的全排列。组合后的收益重新测量，不能把单项倍数相乘。

工程收益以重复窗口明显超出噪声、且包含必要开销为准；例如约 10% 的稳定完整更新提升可作为进入下一阶段的工程筛选线，小幅但几乎无成本的改动可以单独保留。微核很快但全更新不快的候选停止扩大。

**首批落地选择：完整 Bio 加大 batch；共享因子和读取布局精简；空间计算与慢状态的前向/反向融合。** 这三件事最直接对应我们已经测到的瓶颈。当前不预先承诺达到 Transformer 的某个百分比，新的完整更新与同质量墙钟会给出可用答案。
