# Bio-Matrix v0.4：信号、历史适用性与动态矩阵网络

> 归档说明：本文保留写作时点的设计或状态。项目已停止v0.9后续训练；最新执行状态见[实验索引](RESULTS_INDEX.md)。公开副本不含权重与语料。

实现日期：2026-10-22。源码独立放在 `v04/`；入口为项目根目录 `run_biomatrix_v04.py`。旧版实现与结果不修改。

## 1. 本轮冻结的计算对象

这是完整核心闭环的一种明确参数化：结构化观测 → 矩阵预测与创新 → 潜在情景竞争 → 概率记忆写入 → 动态外部映射 → 稀疏矩阵通信及多频耦合 → 直接内容读取。固定训练参数与运行时状态分离。不加入 JEPA、新优化器或额外语言模型。

输入是中文可读、机器可解析的设备观测流。它不是中文自然语言建模数据。已知地址采用固定 one-hot，观测值采用四维颜色证据并补零至矩阵维数；这样键和值无法通过编码器坍缩逃避预测。下一阶段再单独研究可学习的自然语言编码，届时需要额外的表示约束。

一次流内没有 RESET、世界编号或边界标记。模型看到：设备地址、当前观测、来源标准差、来源编号、报告编号、四维带噪情景线索及查询。标准差属于可观察的来源元数据；目前不学习未知来源的真实可靠性。来源编号与标准差冗余，当前计算使用标准差。隐藏世界、真实颜色、查询损失掩码、任务类别、颜色旋转编号只用于生成和评分。

## 2. 状态与时间尺度

每个流维护 C=3 个潜在情景槽，每槽 N 个节点。每节点保留：

- M∈R^(d×d)：持久关联矩阵。
- X∈R^(d×d)：快速反应矩阵。
- P∈R^(d×d)：键空间协方差，采用各值通道共享的近似。
- K=4 个模式的二维相位坐标、振幅与频率，共 4K 个浮点数。

单节点共 3d²+4K 个状态浮点数。还保留情景线索均值、占用情况、上次活动时间、情景概率，以及有界的报告编号缓存。d=8 时各模型状态容量精确相同；激活与梯度存储额外计量。

长期训练通过 AdamW 更新基础规则；运行时观测更新 M/P；一次观测内 J=12 轮通信更新 X 和动力学变量。跨内部轮次不会重新更新观测后验。跨 BPTT 分块保留运行状态，只截断梯度；不同独立流从新状态开始。推理可以通过显式 state 参数持续任意多个分块。

## 3. 信号、差值与情景选择

地址 k 与值 v 处于固定公共坐标系。观测前计算：

    v_hat_c = Σ_i write_weight_i · M_(c,i) k
    e_(c,i) = v − M_(c,i) k
    C = v kᵀ                  当前内容包
    D_(c,i) = e_(c,i) kᵀ      创新包

情景得分由带噪线索匹配、上一时刻情景概率与观测预测误差组成。一个宽泛的新情景候选与旧槽竞争。新候选概率超过 0.5 时，分配空槽；槽满时替换最久未活动的槽。线索尺度、新情景偏置、内容误差权重参与训练。读取使用情景混合；写入再乘节点端口和独立写入门，不把“少读旧历史”直接等同于删除旧历史。

这是可训练的有限混合过滤器，含硬分配和有界容量；不是精确贝叶斯情景后验，也没有证明能解决不可辨识情景。当前数据的不同世界具有可分但带噪的线索，同线索下的局部状态变化则另设 partial 任务。没有可区分线索且无新证据的任意隐藏切换仍待测试。

## 4. 概率写入与重复证据

全模型及 probability 组使用带过程噪声的 Joseph 形式更新。令 r 为观测方差，g 为情景责任、节点端口与写入门的乘积：

    P_minus = P + q I
    K_gain = P_minus k / (r + kᵀ P_minus k)
    K_eff = g K_gain
    M_next = M + (v − M k) K_effᵀ
    A = I − K_eff kᵀ
    P_next = A P_minus Aᵀ + r K_eff K_effᵀ

每条新报告只执行一次。缓存中的相同报告编号跳过 M/P 更新，也不再作为新的内容似然参与情景评分。线索本身仍可以在各时刻被观察。内部循环中的消息属于推导和通信，不作为独立外部测量收缩 P。

有界缓存当前为 64 个编号；超过缓存跨度的复制、不同编号的相关来源以及值通道之间的完整相关性尚未覆盖。matrix/fourier 组将协方差与观测方差固定为单位量，只保留确定性门控的关联更新。

## 5. 节点内反应与动态外部映射

外部左映射由基础矩阵与当前 M/X 调整：

    L_eff = L0 + α [tanh(M) + tanh(X)] / sqrt(d)
    input_matrix = L_eff C R0 + innovation + learned_local_drive

当前内容与创新始终有明确通道；历史无法通过输入编码把冲突值过滤成零。持久 M 按上述规则更新，X 通过有界松弛反应演化：

    X_next = (1 − dt·rho) X
             + dt·rho·tanh(A_i X + X B_i + input_matrix + message + 0.2 tanh(M))

A_i/B_i 包含共享基础矩阵和由节点角色产生的对角修正。长期参数共享，角色与独立运行状态使节点具有不同响应。该参数化保留双侧矩阵作用，不把矩阵仅作为改名后的向量。

## 6. 多维矩阵傅里叶通信

固定、无向、每节点 8 条候选边，复用 v0.3 的图生成器。内容、状态不确定性、节点角色和动态模式产生边权，并在候选边中选择 4 条活动边。每条边传递的仍是矩阵：

    T_ij[X_j] = Σ_r a_ijr(Δφ) L_r X_j R_r
    a_ijr = a0 + Σ_h [ac_h cos(n_hᵀ Δφ) + as_h sin(n_hᵀ Δφ)]

频率索引含四个单模式和三个相邻混合模式，形成多维相位差上的截断傅里叶展开。因而整体算子的傅里叶系数为矩阵到矩阵的双侧线性算子。振幅、频率由当前节点状态调节；局部相位耦合反过来改变通信系数。非振荡组用等维非周期坐标替代，保留相同状态预算。

这里的傅里叶是相位差函数的展开，没有对任意节点编号执行 FFT。时间频谱和图拉普拉斯谱尚未作为额外处理层加入。动态专家群具体化为重叠的、随输入和状态改变的局部活动子图；没有声称学出了可命名的独立专家，也没有通过路由跳过所有节点计算。

## 7. 输出、训练与对照

查询直接读取 M k 和 X k，经共享的内容读出与校正得到四类概率，再按情景概率混合。两设备组合题使用所有模型共享的模 4 概率卷积，不把预先给定的算术算子当作学到的推理能力。

五组：

| 组 | 节点 | 概率状态 | 傅里叶/振荡 |
|---|---|---|---|
| graph | 普通门控向量图网络 | 无专门矩阵后验 | 无 |
| matrix | 动态矩阵 | 固定单位协方差 | 等维非周期辅助状态 |
| probability | 动态矩阵 | 有 | 等维非周期辅助状态 |
| fourier | 动态矩阵 | 固定单位协方差 | 有 |
| full | 动态矩阵 | 有 | 有 |

graph 共享情景控制器、端口、输入编码和读取规则。其节点向量维数严格等于矩阵组全部节点状态元素数；用有用的因子层宽度尽量匹配参数，并逐次报告实际差值。它因此是普通图节点对照，不能被描述成标准 Transformer 或纯无结构 RNN。矩阵模型含显式关联更新先验，优势需要结合零训练表现与学习曲线解释。

损失为查询 NLL 加 0.05 倍的观测前预测损失，后者用于训练情景与记忆机制；无隐藏情景监督。BPTT=16，流内状态不清空；矩阵内部迭代启用反向重计算以降低激活内存。学习率共享为 0.001，首轮不按测试集调参；该默认值尚未经过等预算的学习率搜索。

每组颜色反事实四元组逐查询严格平衡。相同种子的全部模型读取相同流序列；32/128/512 各完成五组之后再补种子。默认两种读取路径，共 90 个条件，每条件 1200 个优化更新。小规模表现不会阻止后续规模运行。

## 8. 指标与证据要求

保存训练 NLL/准确率/梯度范数、独立开发集损失、测试 NLL/准确率、Brier、ECE、分任务末次查询表现和逐查询概率。开发集从 step=0 起选择 best，测试集仅在训练完成后读取；另保存零训练测试结果及训练收益。

每个完成条件补充 reset_history、swap_history、no_messages、no_coupling、fixed_external 干预。历史重置/交换发生在查询时刻的当前输入之前，因此独立情景末次查询仍能使用当前观测。报告历史收益、旧情景返回收益、无关历史引起的概率总变差，以及四元组输出多样性。干预可能有分布偏移，需联合解释。

每个规模先运行 shared 路径检查记忆、适应与概率机制，再完整运行 separated 路径，将写入与读取节点分居图的两半；connected/cut 图使用相同的端口分区。只有 separated 与断图/消息干预共同支持时，才能讨论跨节点协作。此后还需固定总容量、固定计算预算、更多种子和公开任务验证；这些条件没有在本次短程实现检查中执行。

## 9. 工程行为与结果状态

项目根入口无需依赖 PyCharm 工作目录。默认 auto 优先 CUDA/MPS，均不可用时明确显示 CPU。进度条显示总条件、当前更新、NLL、准确率和开发集最优损失；tqdm 同时显示速度和 ETA。

每 25 步保存原子 last.pt，开发集改善时导出 best.pt。last 同时包含当前模型、优化器、最优模型、数据 RNG、CPU Torch RNG、数据顺序哈希和完整协议。前向没有随机采样；跨设备浮点结果不承诺逐位相同。源码、协议或设备发生变化时拒绝混入旧目录。

首次 Ctrl+C/SIGTERM 请求在完整更新结束后保存；第二次中断立即退出，保留最近安全检查点。PyCharm 强制 Stop 可能来不及保存当下更新，仍可恢复之前的原子检查点。训练器锁阻止同一输出目录双开；启动后恢复中断项，跳过完成项，后续条件保持 not_executed。

CPU/GPU smoke 属于工程检查。正式 90 条件扫描、公开中文 LLM 对照、固定总容量实验和未知来源可靠性实验均应明确标记为未执行，不能从 smoke 准确率推断构想成立。

## 10. PyCharm 默认队列

先完成 seed=11、N=32 的 shared 五组与 separated 五组，再依次进入 N=128、512；然后重复 seed=23、37。共享端口结果不会阻止分离端口或更大规模运行。graph 与 full 在默认配置下分别为 14,198 和 14,216 个训练参数，差约 0.13%；N 改变运行状态容量，基础参数共享。合成任务含显式更新先验和已知算术读出，零训练对照是必要解释依据。

## 11. 控制器边界

潜在情景控制器会聚合写入端口的预测误差，并向所有节点广播情景责任，因此它是一条全局控制通路。separated/cut 主要检验矩阵内容的局部传递；尤其对可学习向量解码的 graph 组，不能只凭断图成绩归因于邻边通信，需同时检查情景责任是否携带答案相关信息。正式结论应结合全局控制固定或局部化的追加对照。
