## 核心比较

| 条件 | 定义 | 主要问题 |
|---|---|---|
| content_only | 从零训练的纯当前内容投影与同类输出头 | 完整 Bio 是否超过充分训练的当前内容基线 |
| v09_dense | 完整 v0.9、满节点 | 完整节点状态与经验的效果 |
| v09_sparse50 | 完整 v0.9，课程后目标 50% 组预算 | 质量与实际执行成本的折中 |
| transformer | 两层四头、参数接近对应 v09_dense | 与标准因果架构的比较 |

节点规模 32/128/512，模型种子 11/23/37。四类×三规模×三种子为 36 个配对格。content_only 的预测函数、初始化与状态不依赖节点数，每种子只训练一次，三个规模引用同一结果，合计 30 条独立训练。配对格不是额外独立种子。Transformer 按实际形状与完整训练协议去重；当前三个规模的匹配形状不同，分别训练。本轮保留 Bio/内容基线/Transformer、dense/sparse 和规模比较，不再进行完整同预算的 v0.8/v0.9 版本比较。

content_only 是独立从零训练的模型。完整 Bio 检查点关闭 Bio 读出的同权重干预另做，二者回答不同问题。纯内容基线只保留实际用于预测的参数，不能把未执行的 Bio 参数计入其容量或用完整 Bio 的耗时冒充其速度。

队列顺序为 seed11 的 N32 四格→N128 四格→N512 四格，再补 seed23、seed37。每个配对格依次为 content_only、v09_dense、v09_sparse50、transformer。复用 content_only 时直接引用已完成结果。任何规模是否胜出都不影响其他规模的执行资格。

## 固定训练预算

- 每条独立训练 12,000,000 个有效目标；共 360,000,000 个有效目标。PyCharm 入口可在启动新目录前调整预算。
- B2，序列/BPTT64，C16，d8，三快时间带，四轮空间传播，4096 BPE，FP32；保持完整 Bio 机制。
- 固定公开 WikiText-2 数据、train-only tokenizer 与全部文件哈希。所有条件共享数据顺序、有效目标 mask、输入与会话重置协议。
- 会话长度 4096；Transformer context_limit 同设为 4096。所有模型具有相同的会话输入机会，参数、实际持久状态字节与计算成本分别公开。
- 沿用连续文档/干扰/返回流；来源信息只进日志，不进入节点、选路、反馈或损失之外的模型控制。仅会话开始重置；跨文档 next-token 目标按共同 mask 排除。
- AdamW；内容/输出主干 3e-4、Bio 控制 1e-4、时间/局部速率标量 3e-5。Transformer 的注意力与 FFN 明确归入内容主干，修正旧前缀分类造成的意外低学习率。bias、norm、raw 标量无 weight decay。
- 学习率 warmup/cosine 从第一步按最终预算定义；恢复不重启日程，不允许偷偷延长预算。全局 clip1，训练记录全局梯度范数、学习率、loss 与非有限值；分模块梯度通过独立诊断检查。
- 12M 日程下软门预热到 1.2M；稀疏预算在 1.2M–3.6M 收紧。3M 时尚未到目标 50%，4M 检查点才用于查看稳定目标预算。实际节点比例包含必选路径、探索与取整。
- 保存 0.25M、1M、3M、4M、8M 与预算末尾里程碑，实际计数取首次跨过阈值的完整更新，记录超出量。`last` 周期保存，`best` 依据冻结 validation 监测集保存。主比较使用固定预算末尾 `last`，`best` 为次要结果。

若另开真正的 3M pilot，应从开始锁 3M 日程，后续 12M 从零另开。不能把 12M 日程的 3M 中期记录当成一个完成了 3M 日程的实验。

## 评估

训练期间每 0.5M 有效目标查看固定 128 个 validation 冷窗口，作为进度监测。每条训练完成后，自动评估该条 `last.pt` 的同龄暖历史；保留逐窗口/文档原始结果与样本哈希。

默认历史 A0 为 1024 token、共同近期上下文 R 为 256、干扰 B 为 64、评分目标为 256。窗口及前缀均按 C16 对齐。相同模型种子之外，所有模型共享同一评估数据种子与目标位置。优先选择不重叠的评分位置，并公开实际覆盖与文档数。

对同一目标分别计算：

1. `A0 R → Y` 与 `U0 R → Y`：相关历史与等长其他文档干扰。
2. `block_shuffle(A0) R → Y`：保持块内局部顺序的远史顺序干预。
3. `A0 B R → Y` 与 `U0 B R → Y`：相同干扰后的相关历史保留。
4. 同一暖状态的信用失效控制、清除 slow、基础内容读出消融：分离旧信用、慢内容和其他动态读出。

明确保留一个公共已知输入 anchor：评分段包含 T 个输入与其后 T 个目标，anchor 自身概率不计分。所有 prefix 后干预都发生在评分输入前；不把一个早已发出的首预测混入干预效果。

所有模型参数在评估时冻结；自然文本反馈只消费已经观察到的输入，不能提前用目标更新产生该目标的预测。v0.9 按完整块前向评估，禁止复用会因逐 token diagnostics 提前提交部分块的旧评估路径。

报告 NLL、前16/64/256目标、相关历史收益、干扰后保留、清 slow 成本与完整/基础读出差。自然其他文档是干扰控制，不能据此证明严格统计独立。逐文档 bootstrap 只描述评估样本不确定性，三个训练种子逐一报告配对差值、均值与范围，不把窗口数当作训练重复数。

WikiText-2 先前已经多次查看，此轮属于版本比较与探索性机制验证。独立确认需冻结架构后使用此前未参与选择的公共数据；若采用 WikiText-103，必须核查与 WT2 的共享 valid/test 及文章近重复，不能只换数据集名。

严格独立后验与规则修订保留为单独公开任务阶段，优先适配 Zoology/MQAR 官方生成器。其 query 标签不是输入的下一个 filler token，不能直接套自然语言的自动反馈规则。原版先使用无运行时答案反馈的共同协议；“预测后揭示答案”的扩展必须让揭示内容同时进入所有模型，并单独报告。本地入口不会把未适配的任务计为已完成。

## 结果、进度和恢复

默认一次只跑一个本地训练子进程。父界面每秒原位更新总有效目标、已完成训练、当前 seed/N 的四条模型进度、验证阶段和本地资源，共八行。子进程控制台重定向到每组日志，不刷父控制台。

每组保存模型/优化器/完整运行状态、RNG、数据游标、课程和预算计数、源/配置/数据哈希、原始训练与验证 JSONL、best/last 与里程碑。整个队列保存配对格→独立任务引用、状态注册表、汇总和报告，作为跑完后分析的入口。

重启核对同一配置和源码，从 last 恢复未完成训练，已完成训练不重跑；评估失败单独保留，重启只重做评估并归档旧尝试。失败任务不静默换种子、减 batch 或自动重试。Stop 请求等待当前更新完成并保存；强杀最多回退到上个安全检查点，未提交日志尾部保留。

状态区分 not_executed/running/completed/failed/aborted，训练与评估分别记录。质量暂时落后不触发提前终止；NaN/Inf、状态不变量失败、数据损坏、泄漏、OOM 或用户停止时保留现场。

取消 v0.8 后的新队列已生成计划，等待在 PyCharm 点 Run；新目录初始进度为零，不恢复旧 v0.8。12M×30 在当前 Mac 上仍会是多天至数周的任务。已有 context256 短测速只能用于粗略估算，context4096、验证与保存成本另计。实际时间按队列真实有效目标/秒滚动显示。
