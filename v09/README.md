## 实际实现

每节点保留完整多时间带快矩阵、慢经验矩阵、m/P 与 Joseph 更新、相位/Fourier、动态内外映射、trace/support/innovation、有限信用与输出反馈。默认快递推使用本机 d8 实测较快的 sequential rank-one；parallel/triangular 保留为同方程验收与硬件实验。

1. **当前内容基础通路。** 正交投影的完整 d×d 内容从入口沿现有合法径向父边逐轮传递；不重复乘弱幅度门。只有真正到达实际读口的内容参与基础汇聚。图切断后通路同时切断。动态外部矩阵映射、注意力、相位、快慢经验继续作为有界修正参与读出。γ 初值 0.1、范围 (0,0.3)，F1 的直接慢读方向同步包含 γ。
2. **轻量地址。** `address_size=8` 只压缩矩阵匹配 Q/K，Value 与状态保留完整矩阵。`address_size=0` 使用旧完整 Frobenius 地址。
3. **复用固定代数。** 块内历史特征统计与控制器固定投影复用；Fourier 的两个端点分别投影后沿边组合，bias 只加一次。`reuse_controls=False` 保留参考计算。
4. **反馈批量化。** 整块预测的期望 embedding、F1 方向及局部提议批量计算；信用字段每块重建一次。Joseph、按 query 的容量投影与真正依赖前态的更新仍按时间顺序执行。`batch_feedback=False` 保留参考提交。
5. **实际节点组执行。** 先根据块起点历史摘要选组，再 gather 紧凑节点状态、重映射合法边，执行控制/映射/快递推/读取/慢提交，最后 scatter 回完整状态。不同 batch lane 独立选路；相同路由合批，分歧路由分批。路由与收集/回填成本计入整网时间。
6. **训练课程。** v09 `training_progress` 前 10% token 逐渐从软门过渡；前 10% 满节点，10%–30% 才逐步收紧至目标活跃比例。实际激活数量包含必选路径、分组取整和探索预算。
7. **同一块时序的逐 token 参考推理。** `initial_stream_state`/`step` 重算已经到达的当前块前缀，满 C 才提交候选状态，输出与完整块前向一致。`flush_stream` 明确结束部分块。中途改变参数、预算、配置或运行开关会报错。

## 传播、空闲与信用规则

- 保留原球图，包括同层及双向候选边。旧图实际 level 为 0..shells，读口在 level=shells−1；本轮依据实际 `write_ports/read_ports`，未顺手更改几何。
- 基础通路在原图选一条实际入口→读口的径向路径，相关组必选；没有补建跨 cut 的边。
- connected/cut 共用同一静态分区和组表，组预算在分区内独立分配。选择只读历史摘要；不读当前块首 token、整块均值、未来输入或外部来源标签。因此选组本身不会绕过 cut 传递新信号。
- 未执行节点冻结自主状态；未观察到信息不等于观察到零。旧 pending 必须在新选组之前按全局原节点信用消费，可能更新本轮即将空闲的旧节点 slow；随后刷新组摘要。
- 当前读取的未选节点权重/gain 为零；历史信用仍按原节点 ID 滚动、消费和失效。optimizer 更新后只清旧 head 信用，不清记忆内容。
- 监督反馈也服从从入口沿合法边的静态可达域，防止 warm 节点的旧信用把中心观察跨 cut 写入隔离分量。
- 摘要清理与记忆消融同步：`clear_slow`、`reset_fast` 重新计算摘要。

## 对照与归因

默认按每个规模先跑完 6 个配对条件，再进入下一规模：

| 条件 | 内容/地址 | 执行预算 | 用途 |
|---|---|---|---|
| v08_seq | v0.8 原规则 | 全节点 | 当前版本参考 |
| v09_E | 关闭新基础内容、完整地址 | 全节点 | 复用/批处理的代数等价对照 |
| v09_dense | 新基础内容、低维地址 | 全节点 | 新动力学候选 |
| v09_sparse75 | 同上 | 目标 75% | 分组选择候选 |
| v09_sparse50 | 同上 | 目标 50% | 分组选择候选 |
| transformer | 因果两层 Transformer | 参数接近 v09_dense | 工程吞吐参考 |

32/128/512 共 18 条；每条 B2/T64/d8/C16、FP32、6 次预热、3 次主计时和 1 次额外同步剖析。数据为冻结 WikiText-2 官方切分与 train-only 4096 BPE，复验全部原始和准备文件哈希。同规模共享相同连续训练窗口。几次更新用于数值与工程检查。

名义 50% 不等于实际执行一半：小图的必选路径和探索槽可能使全部组活跃。报告公开真实节点数/比例、各 lane 路由、状态容量和参数。当前紧凑执行仍有 Python 分组及小规模设备→主机选择，CUDA 专用融合内核未实现。

摘要路由使用硬选择索引；选中地址通过动态读出残差的连续振幅得到代理梯度，探索槽覆盖其他组。当前没有参考注意力蒸馏或直接的离散排名监督，路由质量需用 summary/cyclic 等预算对照验证。

**基础内容通路是一个刻意设计的当前 token 基线。** 在单入口、所有父边可达的情况下，恒等传递的基础项等于该 token 的线性内容投影。它恢复可辨认输入，但其自身不能证明经验有用。`runtime_bio_read_enabled=False` 为同权重基础项读出消融：状态仍完整执行，不声称省计算。诊断要比较完整/基础项、清慢记忆、历史干预；正式收益需要分别训练的内容基线与重复种子。

## 验收和原始结果

CPU FP64 验证等价实现的输出、全部状态和全部参数梯度；FP32 检查硬门、零到达、容量与概率边界。另检查断图、不同 batch lane、未来扰动、信用换组、空闲状态、流式块时序及参数/协议变更。测速前再在原生设备验证 E 对照和稀疏内容 sequential/triangular。

新结果目录拒绝覆盖；每条件保存 `raw.jsonl`、配置、状态、`last.pt`，全局保存源码快照/哈希、数据清单、设备、验证、registry 和报告。条件明确区分 not_executed/running/completed/failed/aborted。`profile.regions` 为同步前向区域耗时，反向单列；前向区域和不能当成各区域反向耗时。

正式长训还需判断：公开开发集质量、相关历史收益、独立后验污染、A→B→A 恢复、重复种子与固定状态预算。此版本不自动下载新大型数据、不触碰封存 test、不把同步曲线或单次 NLL 改善当成成功。

逐 token reference 采用前缀重放，C16 每完整块处理 1+…+16 个 token，平均约 8.5 倍主体 token 工作；C32 约 16.5 倍。这是因果时序参考，尚需增量实现后才适合高吞吐生成。
