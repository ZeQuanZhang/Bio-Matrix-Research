# 本地 33 万参数架构比较：方法与数据审计

日期：2026-11-03。审计对象为本轮 Qwen3.5 / DeepSeek-V4 微型配置及其复用的 V3 对照；审计期间没有训练模型、修改实验源码或重写检查点。原始训练、预测和既有报告保留。

## 判断

这是一轮记录完整、样本配对严格的先导实验。它支持六种**指定微型配置在当前训练配方下**的性能排序。关于 Bio 架构普遍优于 Qwen / DeepSeek、动态记忆已成功、扩大训练或参数即可获得竞争力，现有证据均不足。

此前将“共同问答失败”优先归因于容量和训练量、据此鼓励直接扩大规模，解读偏乐观。共同失败也可能来自配方、初始化、任务难度、裁剪后的可回答性或实现问题。此次审计没有隔离这些原因。

WikiText-2 和 SQuAD 都有正式研究与公开来源。当前主要问题集中在使用方式、验证规模和基线适配。应先修实验设计，再决定完整 0.133B × 10B-token 训练的投入。

## 已核对的可靠部分

- 64 份冻结源码哈希全部一致；已准备数据与官方原始数据的 SHA256 均通过核验。
- 新增六条训练的 6144 个更新位置，输入和监督 mask 哈希逐步匹配原 Transformer 同种子记录。
- 全部从零训练、共用 4096 词表和初始词嵌入；总参数约 33.3 万、数据和训练目标预算一致；三种子都完成。
- WikiText 分词器只在 train 拟合；训练、验证、保留测试之间无整篇规范化文档重合。SQuAD 按文章切分，文章 ID、标注段落、问题 ID、完整历史哈希跨切分交集为零。
- 全部 61,534 条已准备问答的答案解码、可见答案字串、监督位置和 EOS 存储位置检查通过。三个切分的答案证据到作答位置距离均大于 256 token。

这些检查支持数据完整性与执行可复现性。模型性能、训练配方和机制解释仍须各自验证。

## 数据集与实际评分范围

| 项目 | 数据准备 | 这轮实际使用 |
|---|---|---|
| WikiText-2 train | 629 个准备后分段文档，3,084,660 个本项目 BPE token | 每种子抽取 1,048,576 个目标，独立目标位置约 87.1–88.2 万，覆盖 train 28.2–28.6% |
| WikiText-2 validation | 60 个分段文档，322,869 个 BPE token | 64 窗口、28 文档、8192 次评分，7971 个独立目标位置；221 次重复评分 |
| SQuAD 派生 train | 83,484 题经过筛选，留下 51,416 题、420 篇文章 | 512 更新 × batch4 = 2048 次抽题；独立题数 2002–2010，仅覆盖准备后 train 约 3.9% |
| SQuAD 派生 validation | 4115 题经过筛选，留下 2553 题、22 篇文章 | 64 个不同问题、60 个标注段落、20 篇文章、475 个答案目标；约占准备后 validation 2.51% |
| 保留测试 | WikiText 官方 test；SQuAD 官方 dev 的筛选后版本 | 本轮比较未评分 |

本文的 SQuAD “test” 是项目自行保留的官方 dev 派生集；SQuAD 官方竞赛隐藏测试集仍由组织者保管。

WikiText 原论文将其定位为语言建模语料；它适合检查下一 token 学习，但本轮是自定义 BPE、文档内随机窗口、仅评分窗口末尾 128 token 的口径。论文中的词级 PPL 与此处数值不可直接比较。分词和上下文评分方式都会改变 PPL。来源：[WikiText 原论文](https://arxiv.org/html/1609.07843)、[Transformers PPL 文档](https://huggingface.co/docs/transformers/perplexity)。

64 个窗口足以做快速开发诊断。对整个语料或多领域性能下结论，需要扩大为预先固定的覆盖式验证；当前 bootstrap 只能反映三个已观察种子及所选验证文档的条件性变化。重复使用同一验证集进行多轮设计，进一步限制了它作为最终独立证据的资格。

## 问答构造的关键问题

1. **任务经过强烈筛选。** 准备时要求答案在历史较远处，且答案首 token 不能出现在最近 256 个 token 中。train 保留率为 61.59%；其中 21,853 道题首先因“近处出现答案首 token”被排除。这个条件改变答案与上下文分布，也在设计上削弱了短窗口对照获取直接证据的机会。
2. **裁剪可能删掉必要语境。** 64 道评分题的答案字串均存在，但只有 19 道保留完整原始标注段落；另 45 道有段落内容被裁掉。整个 2553 题验证集仅 810 道保留完整原段落。字串存在不保证关系、指代或区分答案所需的信息完整。截断段落仍可能足够作答，实际可回答性需要额外审查。
3. **监督遗漏 EOS。** EOS 已存入序列，却不参与问答损失。这个缺口会使停止作答缺少训练信号。它可以解释一部分长度控制问题；错误首 token 和重复 `the` 还需要单独解释。
4. **出现测量下限。** 六组模型首答案 token 命中率均为零；seed11 同 64 题自由生成 EM/F1 全零、全部用满 50-token 限额。这项任务暂时没有可观察的成功检索信号，微小 teacher-forcing NLL 差异不能替代成功问答。

SQuAD 原任务为读取对应段落后回答人工问题，原论文以 EM 和词级 F1 评分。当前版本应标为“SQuAD 派生的远距离证据压力测试”，与标准 SQuAD 榜单区分口径。来源：[SQuAD 原论文](https://arxiv.org/pdf/1606.05250)、[官方数据与评测说明](https://rajpurkar.github.io/SQuAD-explorer/)。

这项压力测试可以保留。正式比较同时加入原段落完整、证据距离自然分布的任务；再用距离分桶描述记忆优势。短证据问答与少量真实样本过拟合检查可用于定位学习链路故障。关于长期保留、无关历史隔离与 A→B→A 恢复，这轮每个样本重置、512-token 范围的训练也未提供充分覆盖。

## 交叉污染检查结果

额外执行了连续 32 个规范化单词的完全匹配检查，滚动哈希命中后逐词确认：

- WikiText train → SQuAD validation 的全部 2553 个实际裁剪历史：0 命中。
- SQuAD train 的实际裁剪历史 → WikiText validation 全部 60 文档：0 命中。
- WikiText train → WikiText validation：有 3 个验证文档包含长片段重合；本轮评分的 28 文档均未命中。
- SQuAD train → SQuAD validation：有 3 个裁剪历史包含长片段重合；本轮评分的 64 题均未命中。
- 两道 train/validation 问题字串完全相同，但文章、标注段落和历史不同；相同泛化问题本身不能判作答案泄漏。

本轮实际评分样本在这些检查下没有暴露明显重复污染。全量验证存在少量局部重合，扩展评分时应披露或做敏感性分析。本检查覆盖规范化精确重合，未覆盖语义改写、较短重复和外部预训练污染；本轮模型没有加载外部预训练权重。

## 必须拆开的预训练与问答后训

以下为三个种子的 PPL 算术均值，沿用原表统计口径：

| 模型 | 1,048,576 目标预训练结束 | 再做 512 次问答更新后 |
|---|---:|---:|
| Transformer 128 窗口 | 912.97 | 1078.34 |
| Transformer 512 窗口 | 917.15 | 1056.41 |
| Bio 静态 | **779.22** | 916.31 |
| Bio 动态 | 780.14 | **902.83** |
| Qwen3.5 微型配置 | 862.48 | 982.25 |
| DeepSeek-V4 微型配置 | 883.00 | 1024.99 |

Bio 两组在当前配置上的文本预测优势，在预训练结束时已存在。动态地址版的额外收益在这个阶段并未出现：静态版略好。六组在问答后训后，文本 PPL 全部恶化；最终文本指标混合了预训练效果与后训的语言建模退化，今后应分别列为主指标和保持性指标。

作为事后诊断，用每种子**同一批 1,048,576 个预训练目标**统计词频、加一平滑，不看上下文的 unigram 控制，在同 8192 目标上的 PPL 为 998.66、998.29、1001.88。该简单控制说明当前语言学习仍很浅，尤其后训后的部分模型甚至弱于词频控制。这个诊断未经预注册，也没有与神经模型同样进行问答后训，作用限于描述预测难度与退化。

原有历史干预也未给出强记忆证据：替换远处历史后，Bio 动态版 QA NLL 平均只增加 0.000341，文本 NLL 只增加 0.000040。移除整个记忆读出通道会改变数值，但该操作同时改变计算通道，不能单凭它确认正确历史检索。

## Qwen / DeepSeek 对照的代表性

总参数与训练 token 对齐，是有效的固定预算比较条件。此轮结果仍同时受到以下因素影响：

- 总参数约 69% 为词嵌入；剩下约 10.4 万参数容纳序列计算。Bio 两层、两个新配置四层，矩阵宽度与深度分配不同。
- DeepSeek 的每专家中间维只有 8；mHC 占其非嵌入参数约 42.6%，FFN/专家内容参数仅 26,880。当前微型化带来了极高结构开销。只有这一配置，无法估计合理微型配置搜索后的架构水平。
- Qwen 保留 GDN/全注意力混合，但头维、RoPE 和中间层比例经过微型调整；DeepSeek 没有 MTP、索引器蒸馏及官方无辅助损失路由调度。512 长度与 topk512 也没有测出稀疏长上下文的主要收益。公共 Transformers 实现明确标注其 DeepSeek MTP 未实例化。来源：[DeepSeek-V4 实现文档](https://huggingface.co/docs/transformers/model_doc/deepseek_v4)、[Qwen3.5 实现文档](https://huggingface.co/docs/transformers/model_doc/qwen3_5)。
- 共用学习率、优化器和预算，但其余初始化保留各实现默认，未给每种架构同等的独立调参机会；Bio 已经历较多前期迭代。这些因素混合在当前排名里。
- 对齐训练 token 不等于对齐 FLOPs 或墙钟预算。Mac FP32 参考算子、历史上不同运行时段的用时，适合描述这份实现的本机成本；旗舰 CUDA 内核与速度未测。

语言模型研究已有直接先例：控制超参数搜索后，旧架构可以反超新架构；不同调参计算预算也可能改变模型排名。应为每个模型提供相同的有限搜索机会，同时报告质量随总搜索成本变化。来源：[Melis 等，ICLR 2018](https://arxiv.org/pdf/1707.05589)、[Dodge 等，EMNLP 2019](https://aclanthology.org/D19-1224/)。

## 低成本修正顺序

1. **先验收学习与测量链路。** 新建修正协议和数据目录，补 EOS 监督；检查固定少量真实样本能否过拟合，以及完整短证据问答能否超过全零下限。抽查裁剪后问题的可回答性。旧数据与结果保持冻结。
2. **把纯预训练 LM 作为独立主比较。** 全量或覆盖式 WikiText held-out 评分、显式排除重复目标位置、报告 unigram 控制；问答后训后的 LM 退化单独报告。
3. **给各架构同等调参预算。** 例如先用相同的 3 个学习率候选与相同 token 预算检查敏感性，按开发集选配置，再做种子重复；DeepSeek 至少增加合理容量分配的配置。搜索与最终训练成本都记录。
4. **将标准任务与机制压力测试并列。** 完整自然证据问答 + 距离分桶；配对无历史、无关历史、远处证据替换干预。用生成 EM/F1、首答案命中和干预效应验证正确利用历史，避免只凭平均答案 NLL 宣布记忆有效。
5. **保留真正独立的最终评分。** 当前 64 样本继续做开发诊断；模型和协议确定后再评项目保留测试，不用最终测试反复调参。扩大规模前先完成短预算学习曲线与 CUDA 资源/吞吐剖析，再决定 10B-token 投入。
